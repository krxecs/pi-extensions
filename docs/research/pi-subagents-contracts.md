# `@gotgenes/pi-subagents` contracts at 25.0.5

Research for [Inventory pi-subagents public contracts and design choices](https://github.com/krxecs/pi-extensions/issues/3). This is an inventory for later Pi RPC and ACP decisions, not a parity specification.

## Source and scope

The npm registry's [25.0.5 metadata](https://registry.npmjs.org/%40gotgenes%2Fpi-subagents/latest) identified version `25.0.5`, the `gotgenes/pi-packages` repository, the Pi extension entry `./src/index.ts`, and two package exports: `.` (types `dist/public.d.ts`, implementation `src/service/service.ts`) and `./settings` (types `dist/settings.d.ts`, implementation `src/layered-settings.ts`). The published tarball's README and `src/service/service.ts` match the files at the pinned [pi-subagents-v25.0.5 tag](https://github.com/gotgenes/pi-packages/tree/a4dd5f7611a2d7687a50899e99be7bd727ddc2b0/packages/pi-subagents) byte for byte. Links below use that commit, not the moving `main` branch. The package is a hard fork, so upstream `tintinweb/pi-subagents` is not the authority for these contracts. [README introduction][readme-intro]; [package manifest][manifest].

There are three different integration layers. The package exports a typed service and settings loader; Pi's event bus carries agent, settings, and child-session events; Pi tools and commands are user/model interfaces, not service methods. A child-session event is not an exported `SUBAGENT_EVENTS` constant merely because its source declares a constant. [Service export][service-export]; [child event declarations][child-events]; [registration][index-registrations].

## Pi event inventory

Every row below gives the **actual emitted object**, including fields the README calls only "key fields." The first eight agent channels have names in `SUBAGENT_EVENTS`; `subagents:update` and the two settings channels are emitted but absent from that constant. The five `subagents:child:*` channels are declared in a source module, not re-exported by the package's root declaration. Subscribe by string where there is no exported root constant. [Event constants][service-events]; [published declarations][public-declarations]; [agent observer][observer]; [settings emitter][settings-events]; [child publisher][child-events].

| Channel | Emission and exact payload shape |
| --- | --- |
| `subagents:created` | Background record registered **before queue admission**: `{ id: string, type: string, description: string, isBackground: boolean }`. Foreground spawns do not emit it. [Manager creation][manager-create]; [observer][observer] |
| `subagents:started` | Initial run begins, including after dequeue: `{ id: string, type: string, description: string }`. It is not emitted on resume. [Observer][observer] |
| `subagents:completed` | Initial run ends with `status: "completed"`: the terminal object defined below. [Observer][observer]; [status classification][statuses] |
| `subagents:failed` | Initial run ends with `status: "error" | "stopped" | "aborted"`: the same terminal object. A queued stop can reach this channel without a child session. [Observer][observer]; [status classification][statuses]; [manager abort][manager-abort] |
| `subagents:resuming` | Resumed run begins (after admission if queued): `{ id: string, type: string, description: string }`. [Observer][observer]; [manager resume][manager-resume] |
| `subagents:resumed` | **Any** resumed run ends, successful or not, including a queued stop: the terminal object below; inspect `status` and `error`, not the channel name, to determine success. Initial `completed`/`failed` subscribers do not see resume endings. [Observer][observer] |
| `subagents:steered` | Accepted/buffered `steer_subagent` **tool** call: `{ id: string, message: string }`. The service adapter's `steer` does not emit this channel in its own code; do not assume it does. [Steer tool][steer-tool]; [service adapter][adapter-steer] |
| `subagents:compacted` | Successful child compaction: `{ id: string, type: string, description: string, reason: "manual" | "threshold" | "overflow", tokensBefore: number, compactionCount: number }`. [Observer][observer]; [compaction type][compaction-type] |
| `subagents:update` | Child `notify_parent` message during a run: `{ id: string, type: string, description: string, message: string }`. It is not in `SUBAGENT_EVENTS` or the README's event table, but is emitted and announced to the parent. [Observer][observer]; [child tool][notify-tool] |
| `subagents:settings_loaded` | Load at extension initialization: `{ settings: SubagentsSettings }`, where `settings` is the **loaded, sanitized merged file values**, not the full defaults-filled runtime snapshot. [Settings load][settings-load]; [settings shape][settings-shape] |
| `subagents:settings_changed` | Mutation via settings handler: `{ settings: SettingsSnapshot, persisted: boolean }`. A failed write still emits the event with `persisted: false`; the snapshot has required runtime fields and optional `excludedExtensionPackages` and `promptInheritance`. [Settings save][settings-events]; [snapshot shape][settings-shape] |

The **terminal object** produced by `buildEventData(record)` is exactly `{ id, type, description, result, error, status, turnBudget, toolUses, durationMs, tokens }`. Types are `id/type/description: string`, `result/error: string | undefined`, `status: SubagentStatus`, `turnBudget: TurnBudget | undefined`, `toolUses/durationMs: number`, and `tokens: { input: number, output: number, total: number } | undefined`. The keys exist even when their values are `undefined`; `tokens` is omitted as a value when total usage is zero. `durationMs` uses `completedAt - startedAt` once terminal. `tokens.total = lifetimeUsage.input + lifetimeUsage.output + lifetimeUsage.cacheWrite`; it does not include `cacheRead`. These totals are cumulative across compactions, rather than the current context-window size. [Event builder][event-builder]; [usage definition][usage].

The five **child-session channels** are a separate, source-declared integration convention used by other extensions (for example, permission integration), not part of the root `SUBAGENT_EVENTS` object. [Child event types and publisher][child-events]; [construction sequence][child-construction]; [child completion and disposal][child-session].

| Channel | When and exact payload |
| --- | --- |
| `subagents:child:spawning` | Before session construction: `{ agentName: string, parentSessionId?: string }`. [Child declarations][child-events]; [construction][child-construction] |
| `subagents:child:session-created` | After session creation, immediately **before** child `bindExtensions()`: `{ sessionId: string, parentSessionId?: string }`. A synchronous subscriber can register the child before binding; this event may be followed by `disposed` without `bound` if binding fails. [Child declarations][child-events]; [construction][child-construction] |
| `subagents:child:bound` | After binding and child `session_start`, before the first turn: `{ sessionId: string, parentSessionId?: string }`; skipped on bind failure. [Child declarations][child-events]; [construction][child-construction] |
| `subagents:child:completed` | The **first** child prompt resolves: `{ sessionDir: string, agentName: string, turnBudget?: TurnBudget }`; later resumes do not emit it. It is not a universal error/finally signal. [Child declarations][child-events]; [turn loop][child-session] |
| `subagents:child:disposed` | Child session teardown: `{ sessionId: string }`; after child `session_shutdown` and session disposal, including the bind-failure cleanup path. Usually later than the run's completion because of retention. [Child declarations][child-events]; [session disposal][child-session]; [retention][readme-lifecycle] |

`SubagentStatus` is `"queued" | "running" | "completed" | "aborted" | "stopped" | "error"`. A `TurnBudget` is `{ used: number, maxTurns?: number, phase: "within" | "warned" | "exhausted" }`; successful turns count, an unlimited run has no `maxTurns`, and a budget can be unavailable until the turn loop starts. [Status definition][statuses]; [budget definition][budget]; [README budget][readme-budget].

## Typed extension-author API

Import `getSubagentsService()` dynamically from `@gotgenes/pi-subagents`, declare an **optional peer dependency**, and handle `undefined` if the extension has not published the service. `publishSubagentsService` and `unpublishSubagentsService` are also exported; the extension publishes at setup and unpublishes on shutdown. The accessor uses a `globalThis[Symbol.for("@gotgenes/pi-subagents:service")]` slot, not RPC or a Pi event request/reply. The type declarations also export `SubagentsService`, `SubagentRecord`, `SpawnOptions`, `ResumeOptions`, `ResumeResult`, statuses, usage/budget types, and the workspace types. [README API][readme-api]; [service declarations][service-api]; [service export][service-export]; [extension lifecycle][index-lifecycle].

| `SubagentsService` method | Exact signature and behavior |
| --- | --- |
| `spawn` | `(type: string, prompt: string, options?: SpawnOptions): string`. Returns an ID immediately, including for a queued agent. Throws when no active parent session, model cannot resolve, thinking level is invalid, or a known type is disabled. Unknown/case-varied type resolves to the canonical type or falls back to `general-purpose`. [Service][service-api]; [adapter][adapter-spawn]; [type resolution][manager-create]; [README spawn][readme-spawn] |
| `getRecord` | `(id: string): SubagentRecord | undefined`. A by-value, present-state snapshot, not a live object. [Service][service-api]; [adapter][adapter-lookup]; [snapshot converter][adapter-record] |
| `listAgents` | `(): SubagentRecord[]`. Tracked records, newest first, each copied into a snapshot. [Service][service-api]; [manager list][manager-list]; [adapter][adapter-lookup] |
| `abort` | `(id: string): boolean`. Stops a queued or running agent; `false` if absent (or already not abortable). [Service][service-api]; [manager abort][manager-abort] |
| `steer` | `(id: string, message: string): Promise<boolean>`. `false` if absent or rejected as non-running; a pre-initialization message can be buffered. [Service][service-api]; [adapter][adapter-steer]; [steer result][steer-type] |
| `resume` | `(id: string, prompt: string, options?: ResumeOptions): Promise<ResumeResult>`. Background run, queued behind the concurrency limiter, resolves on terminal status to `{ kind: "resumed", record: SubagentRecord }`; refusals resolve promptly to `{ kind: "refused", reason: ResumeRefusalReason }`. A resumed run ending in `error` is still `kind: "resumed"`. [Service][service-api]; [adapter][adapter-resume]; [README resume][readme-resume] |
| `waitForAll`, `hasRunning` | `(): Promise<void>` waits for running/queued work including new work started during the wait; `(): boolean` reports whether any are active. [Service][service-api]; [manager wait][manager-wait] |
| `registerWorkspaceProvider` | `(provider: WorkspaceProvider): () => void`. One provider at a time, registration throws if occupied; disposer unregisters it. `prepare({ agentId, agentType, baseCwd })` returns `Promise<Workspace | undefined>`; workspace has `cwd` and `dispose({ status, description })` returning optional `{ resultAddendum?: string }`. Core defaults to parent cwd if no workspace. [Service][service-api]; [provider types][workspace]; [manager provider][manager-provider] |

`SpawnOptions` is `{ description?: string, model?: string, maxTurns?: number, thinkingLevel?: string, inheritContext?: boolean, foreground?: boolean, bypassQueue?: boolean }`. `description` defaults to the prompt's first 80 characters; `inheritContext` defaults to `false` even if an agent file specifies otherwise. Explicit `foreground` overrides agent frontmatter; otherwise its `run_in_background` setting applies, with the service defaulting to background. `bypassQueue` is a caller-level escape hatch; it does not change the public event shape. Caller values for model, thinking, and turns beat agent-file defaults, and agent-file `locked` fields only constrain the model-facing `subagent` tool. [Service options][service-api]; [adapter spawn][adapter-spawn]; [README spawn][readme-spawn].

`SubagentRecord` fields are `id`, `type`, `description`, `status`, `isBackground`, `toolUses`, `startedAt`, `lifetimeUsage: { input, output, cacheWrite }`, and `compactionCount` (required); `result`, `pendingQuestion`, `error`, `turnBudget`, `completedAt`, `outputFile`, `resumeRefusal` (optional). `isBackground` describes the **current or last run** and can change on resume. `outputFile` points to the Pi JSONL transcript. `resumeRefusal` is absent when the record can resume; otherwise it is `"still-running" | "resume-queued" | "no-session" | "session-released" | "workspace-disposed"`. An unknown ID yields the extra refusal `"unknown-agent"`, never a record field. `lifetimeUsage` and `turnBudget` are copied before return. Live tools/partial response, session objects, and delivery bookkeeping are deliberately absent. [Record type][service-record]; [adapter copying][adapter-record]; [README records][readme-record]; [record policy][record-adr].

`ResumeOptions` accepts `claimOutcome?: boolean` (suppress parent completion nudge only if the caller will deliver the outcome) and `signal?: AbortSignal` (cancels the resumed run with status `stopped`). Default resumes notify the parent; the service resume has no foreground option. The six refusal reasons, retention, and workspace constraints matter even if an implementation uses a different transport. [Resume types][service-api]; [adapter resume][adapter-resume]; [README resume][readme-resume].

The other exported subpath, `@gotgenes/pi-subagents/settings`, exposes `loadLayeredSettings<T>(source: LayeredSettingsSource<T>): Partial<T>` with `agentDir`, `cwd`, `filename`, `sanitize`, and `warnLabel`. It shallow-merges `<agentDir>/<filename>` and `<cwd>/.pi/<filename>` (project wins); missing files are silent, malformed files warn and fall back. It is a companion utility, not the agent service. [Package manifest][manifest]; [settings loader][layered-loader]; [README settings API][readme-settings].

## Model-facing tools, commands, and lifecycle

- `subagent` requires `prompt`, `description`, `subagent_type`; optional `model`, `thinking`, `max_turns`, `run_in_background`, `resume`, `inherit_context`. Foreground waits and streams a result; background returns an ID and later notifies. A background **resume** must explicitly set `run_in_background: true`; an agent file's default does not select that mode for resume. A caller's fields override frontmatter unless the agent file locks them. `max_turns` below two runs as two even though the schema accepts numbers from one. [README tool][readme-tools]; [actual schema][agent-tool]; [budget][readme-budget].
- `get_subagent_result` requires `agent_id`; optional `wait`, `verbose`, `timeout` (seconds). Without a timeout, `wait: true` waits until settlement; timeout or parent interruption ends the wait **without stopping the child**. Polling consumes a settled outcome; `verbose` adds the conversation when still available and the report includes the saved transcript path. [README tool][readme-tools]; [implementation][get-tool].
- `steer_subagent` requires `agent_id` and `message`, sends the message after the current tool call, and rejects non-running records. It is distinct from service `steer`, including its event emission. Child-only `ask_parent({ question })` ends the turn and records an answerable question; `notify_parent({ message })` reports a material mid-run update and continues without waiting. `midRunUpdates: false` withholds `notify_parent`, not `ask_parent`. [README tools][readme-tools]; [tool implementation][steer-tool]; [child tools][ask-tool]; [notify tool][notify-tool]; [configuration][config-tools].
- `/subagents:settings` edits project settings (concurrency, turn limit, wrap-up, retention, interrupt policy; the settings UI also handles mid-run updates), and `/subagents:sessions` opens read-only transcripts, including retained records after reload. These are interactive Pi commands, not API methods. [README commands][readme-commands]; [registration][index-registrations]; [configuration][config-settings].

Children run **in process** in isolated Pi sessions, not subprocesses or ACP agents. Background concurrency defaults to four with FIFO waiting; foreground bypasses the queue. The parent interrupt aborts background/queued work by default unless `abortAllOnInterrupt: false`; foreground inherits the parent's signal regardless. On a child, `session_start` occurs after binding, and `session_shutdown` occurs before session disposal, not immediately when a run ends. Completion leaves the session resumable for the consumed/unconsumed retention windows (defaults 10/720 minutes); records remain in the parent session after the live session is released, but cannot resume then. Completed records are cleared on parent session start/switch; shutdown unpublishes the service, aborts work, disposes child sessions, and awaits cleanup. [README lifecycle][readme-lifecycle]; [README concurrency][readme-concurrency]; [configuration retention][config-settings]; [lifecycle handler][handler-lifecycle]; [child disposal][child-session].

A child inherits a stable part of the parent's prompt, builds its own skills/context-dependent parts, and loads the parent's extensions unless packages are explicitly excluded. Agent files live in project `.pi/agents/*.md` or the global Pi agent directory and can set tool allowlists, prompts, models, turn limits, and locking. The child always excludes `subagent`, `get_subagent_result`, and `steer_subagent` for recursion control, while `ask_parent` and (when enabled) `notify_parent` are child protocol tools. These are real reference behaviors; the **specific** prompt construction, tool filtering, and YAML shape are not implied by the event/service signatures. [Configuration agent files][config-agents]; [configuration tools][config-tools]; [configuration inheritance][config-inheritance]; [child factory][child-construction].

## Contract versus design choice for a future Pi RPC / ACP implementation

- Preserve or explicitly version the **integration shapes** if compatibility with existing consumers is desired: channel strings and exact payload semantics, exported names and return/refusal types, snapshot freshness, event ordering, outcome-delivery rules, and model-facing names/arguments. In particular, an ACP child with no Pi `AgentSession` cannot honestly supply a Pi session ID, Pi JSONL transcript path, or `session_start`/`session_shutdown` semantics without an adapter. A service implemented across a process boundary also cannot literally share this package's `globalThis` slot. Those are compatibility gaps to decide, not promises made by this note. [Service][service-api]; [child events][child-events]; [child session implementation][child-construction]; [service publication][service-export].
- The reference **architecture** chooses a minimal core: agent session/execution, concurrency, resume, result delivery, and events; permissions live in a separate extension; worktree isolation is supplied by a single workspace provider in another package. It explicitly rejects core scheduling, cross-extension RPC, binary tool denylist policy, and built-in worktrees. This is useful evidence for locating boundaries, not a requirement that a multi-transport extension copy the same split. [Scope][readme-scope]; [architecture decision][core-adr]; [workspace seam][workspace].
- Widget display, themed notifications, transcript viewer, default `Explore`/`Plan` agents, fuzzy model names, local settings files, prompt-inheritance policy, and FIFO queue implementation are behaviors/design choices, but none is needed merely to consume the typed service or subscribe to events. A later specification should decide each one deliberately, especially which can be represented consistently under Pi RPC and ACP. [README features][readme-features]; [configuration defaults][config-agents]; [scope][readme-scope].
