# ACP coding-agent interoperability

Research for [Map ACP coding-agent interoperability](https://github.com/krxecs/pi-extensions/issues/5), under [Specify a compatible multi-agent Pi extension](https://github.com/krxecs/pi-extensions/issues/2). Source snapshots below are pinned to commits, except Pi, pinned to tag `v1.5.2`. This is protocol and implementation research, not an interoperability test or an extension design decision.

## Answer

**Verified.** An external coding agent that implements ACP can run as a child *process* of a Pi extension acting as the ACP **client**. ACP v1 specifies a client-launched stdio process, newline-delimited JSON-RPC, `initialize`, `session/new`, `session/prompt`, streamed `session/update`, and `session/cancel`. The agent owns its session and tool execution; the client must handle reverse requests such as `session/request_permission`. The official TypeScript SDK supplies a v1 client entrypoint and a subprocess client example. These facts justify a per-agent ACP adapter, not a claim that every agent or every ACP feature works in Pi. [ACP v1 transport](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/transports.mdx), [overview](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/overview.mdx), [SDK README](https://github.com/agentclientprotocol/typescript-sdk/blob/127bd0dccccb69da61e76fc82b0b3f663a5dfa54/README.md), [client example](https://github.com/agentclientprotocol/typescript-sdk/blob/127bd0dccccb69da61e76fc82b0b3f663a5dfa54/src/examples/client.ts).

**Version boundary.** The SDK's default import is stable ACP v1. Its ACP v2 entrypoints are explicitly experimental preview APIs with no compatibility guarantee. V2 changes the lifecycle: `session/load` is removed in favor of `session/resume` with replay, `authenticate` becomes `auth/login`, and `session/prompt` acknowledges acceptance while subsequent state updates mark completion. Do not share a v1 wire handler with v2 or silently negotiate v2 just because an installed agent supports it. [SDK README](https://github.com/agentclientprotocol/typescript-sdk/blob/127bd0dccccb69da61e76fc82b0b3f663a5dfa54/README.md), [v2 migration](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v2/migration.mdx), [v2 overview](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v2/overview.mdx).

## Protocol behaviors to account for

| Topic | Verified ACP v1 behavior and implication for a client |
| --- | --- |
| Setup and negotiation | Call `initialize` before session setup, offer the highest supported protocol major version, check the returned version, and treat omitted capabilities as unsupported. `session/new` sends an absolute `cwd` and `mcpServers` list; it returns an agent-owned session ID. Optional capabilities include prompt images/audio/resources, MCP HTTP/SSE, session resume/load, client filesystem and terminal services, and other session features. Advertising client methods means implementing them, not assuming the agent will never call them. [Initialization](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/initialization.mdx), [session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/session-setup.mdx), [overview](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/overview.mdx). |
| Streams and tools | `session/update` carries text/thought chunks, tool-call and plan updates, and other optional variants. Tool calls are performed by the agent, not dispatched as Pi tool invocations; `name`, `kind`, status, content, and raw input/output are reporting fields. Finish a v1 turn on the `session/prompt` response and its `stopReason`, not on the last chunk. [Prompt turn](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/prompt-turn.mdx), [tool calls](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/tool-calls.mdx). |
| Permissions and safety | The agent may send `session/request_permission` with agent-provided options; the client replies with a selected option ID or `cancelled`. `allow_always`/`reject_always` persistence and scope belong to the agent. ACP does **not** sandbox its process; permission requests are advisory because the agent may execute its own tools. Client-side filesystem and terminal services require separately advertised capabilities and independent checks. Do not auto-approve based on agent-authored titles or option labels. [Tool-call permissions](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/tool-calls.mdx), [security model](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/security.mdx), [initialization](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/initialization.mdx). |
| Cancellation | `session/cancel` is a notification for the active turn, not a confirmed immediate kill. Reply `cancelled` to pending permission requests, keep accepting late updates until the `session/prompt` response, and interpret its `cancelled` stop reason. `$/cancel_request` is an optional, separate JSON-RPC request-cancellation mechanism; an agent may not implement it. An external process can also exit or hang, so local timeouts and process cleanup remain host responsibilities. [Prompt-turn cancellation](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/prompt-turn.mdx), [request cancellation](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/cancellation.mdx), [stdio transport](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/transports.mdx). |
| Resume | `session/load` requires `loadSession: true` and replays history before replying. `session/resume` requires `sessionCapabilities.resume` and restores without replay; both resend `cwd` and MCP servers. Save the agent ID, workspace, launch configuration, and negotiated capability/version before promising restore. Resume is agent-specific; neither method is guaranteed by the v1 baseline. [Session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/session-setup.mdx), [initialization](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/initialization.mdx). |
| Authentication | The initialize result advertises `authMethods`; agent-handled methods use `authenticate`. Terminal methods require the client to advertise terminal authentication, launch an interactive login process, then reconnect and reinitialize. `session/new` can fail until authentication is complete. The extension must not assume Pi's credentials work for another agent. [Authentication](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/authentication.mdx), [session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/session-setup.mdx). |

ACP's optional child-session reporting describes **agent-owned** subagents. If enabled, the agent announces them in `subagent_update`; the client may display their separate updates but does not gain ownership of them. That is different from an extension spawning independent ACP processes itself. Do not conflate either case with Pi-subagents' event-bus IDs or lifecycle. [ACP subagents](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/subagents.mdx), [pi-subagents public events and RPC](https://github.com/gotgenes/pi-subagents/blob/bc4faa30128e08dc9de451909347af927059cd37/README.md#events).

## First-party client reference and candidate agents

Zed's first-party External Agents documentation shows a working ACP client model: it launches agents as separate processes, hosts their threads, and treats agent authentication, model choice, tools, and native configuration as separate from Zed's own settings. It also documents custom agent command/argument configuration and ACP wire logs. This is a comparison target for manual behavior checks, not evidence that an extension will have Zed's capabilities. [Zed External Agents](https://github.com/zed-industries/zed/blob/5e407587312349c6554f28035be99eb0e85f3e90/docs/src/ai/external-agents.md).

These are documented launch targets, **not** measured compatibility results. Install and sign-in steps, supported variants, and replay behavior can change between releases.

| Candidate | Evidence and first test |
| --- | --- |
| Gemini CLI | Its own ACP guide says `gemini --acp` uses stdio JSON-RPC. The source imports the SDK's v1 default, advertises `loadSession`, prompt content and MCP capabilities, implements `authenticate`, `session/new`, `session/load`, prompt, cancel, and modes. Test auth-required setup, a text turn, permission denial, cancellation and history replay. The guide says MCP details are supplied at initialize, but the inspected session manager consumes `mcpServers` in `session/new`/`session/load`; use the source and ACP spec for this detail. ## Boundaries with Pi and pi-subagents

Pi `v1.5.2` RPC is a different JSONL protocol. It exposes Pi-specific commands (`prompt`, `steer`, `follow_up`, `abort`, `switch_session`, `get_entries`) and session events. A successful prompt command means acceptance, not completion; `agent_settled` marks settled work. Pi extension dialogs use `extension_ui_request`/`extension_ui_response`; `ctx.ui.custom()` has no RPC implementation. These are **not** ACP methods, session IDs, or permission requests. A shared UI may show normalized text/tool-status/terminal outcomes, but transport-specific requests and capabilities must stay typed and separate. [Pi RPC](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc.md), [commands](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc-commands.md), [extension UI](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc-extension-ui.md), [ACP prompt turn](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/prompt-turn.mdx).

The reference `@gotgenes/pi-subagents` documents Pi-specific `Agent`, `get_subagent_result`, `steer_subagent`, background queue/group notifications, session resume, and `pi.events` lifecycle and cross-extension RPC (`subagents:rpc:ping/spawn/stop` with request-ID-scoped replies). None of those public names, reply envelopes, scheduler rules, or Pi session semantics is supplied by ACP. Preserving them would be a **host-side compatibility layer** with explicit gaps for an agent lacking steering, persistent sessions, comparable token counts, custom system prompts, or Pi-native tools. The ACP permission option selected by the user cannot be treated as a Pi permission-system decision, and ACP tool reports cannot become actual Pi tool events retroactively. [pi-subagents README](https://github.com/gotgenes/pi-subagents/blob/bc4faa30128e08dc9de451909347af927059cd37/README.md), [ACP session setup](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/session-setup.mdx), [ACP tool calls](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/tool-calls.mdx), [ACP security](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/security.mdx).

## Proposed validation and unresolved decisions

**Proposal, not verified implementation.** Start with ACP v1 and one explicit launch profile per agent. Make the host own process supervision, authorization prompts, deadlines, bounded streams, and any worktree isolation. Advertise only client capabilities actually implemented. Preserve raw transport metadata alongside a small common event model; do not synthesize `resume`, steering, cost, or permission guarantees when the agent has not supplied them. This follows the ACP capability, security, and turn contracts and Pi's separate RPC lifecycle. [ACP initialization](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/initialization.mdx), [security](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/security.mdx), [Pi RPC](https://github.com/earendil-works/pi/blob/b4afdddf44e059c67ccf5097e5317d913521b470/packages/coding-agent/docs/rpc.md).

**Proposed tests.** Run the official TypeScript SDK example against a fake agent for framing, notifications, permission request/denial, pending-request cancellation, process exit, and mismatched version. Then run real authenticated smoke cases against Gemini, Codex adapter, Claude adapter, and OpenCode: new session, streamed text and tool status, deny permission, cancel a long-running tool, resume/replay if advertised, and teardown. Log the negotiated version/capabilities and each agent build. The official ACP TCK can test the *agents* over stdio, but it is experimental, has incomplete coverage, and does not certify our *client*. Its v1 suite is default; v2 requires an opt-in. An auth-gated or too-short cancellation run can skip the very case under test. [SDK client example](https://github.com/agentclientprotocol/typescript-sdk/blob/127bd0dccccb69da61e76fc82b0b3f663a5dfa54/src/examples/client.ts), [ACP TCK README](https://github.com/agentclientprotocol/acp-tck/blob/7c71c4d1af0994e73bdc100c9f7f6b98f2319cda/README.md).

**Still to decide in the map.** Which agents and versions count as release acceptance targets; whether ACP v2 preview or agent-specific `_` extensions are in scope; what user-facing permission policy, sandbox/worktree boundary, login UX, and restart/replay guarantee to promise; whether compatibility events represent only host-created children or also agent-owned ACP children; and which pi-subagents fields are intentionally unavailable for ACP. These are product decisions, not facts established by a registered ACP handler or an agent README. [Map destination and notes](https://github.com/krxecs/pi-extensions/issues/2), [ACP extensibility](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/overview.mdx), [ACP subagents](https://github.com/agentclientprotocol/agent-client-protocol/blob/31062dc430781b27563fc611c9a9c717ee912c93/docs/protocol/v1/subagents.mdx).
