# Dynamic workflows and ultracode behavior

Research for [Compare dynamic workflows and ultracode semantics](https://github.com/krxecs/pi-extensions/issues/6), under [Specify a compatible multi-agent Pi extension](https://github.com/krxecs/pi-extensions/issues/2). Checked 2026-11-23. This compares documented behavior; it does not specify the new extension.

## Source scope

- Anthropic's [dynamic workflows documentation](https://code.claude.com/docs/en/workflows) is a live first-party page, not a pinned release. The version qualifications below are those printed on that page when checked. Do not assume earlier Claude Code releases match it.
- The Pi extension comparison is pinned to [`@quintinshaw/pi-dynamic-workflows` 3.15.3 README](https://github.com/QuintinShaw/pi-dynamic-workflows/blob/4df9c3d25b28eb0bc995ac2e265dafb3190a00ff/README.md) and [package version](https://github.com/QuintinShaw/pi-dynamic-workflows/blob/4df9c3d25b28eb0bc995ac2e265dafb3190a00ff/package.json). Its README is a product contract, with source links below where the mechanism matters.
- Pi's [`codemode` documentation at v1.5.2](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/codemode.md) describes the *existing* Pi tool, not either workflow runner. Differences between Pi's installed v1.5.2 and a future target version need separate verification.

## Boundary and decision prompts

**Verified boundary.** Pi `codemode` is a synchronous, sandboxed JavaScript tool-call orchestrator. It can express branching, loops, and parallel calls to tools already exposed to it. Its own docs do not provide coding-agent spawning, workflow commands, progress UI, a durable run journal, pause/resume, or turn-level opt-in. `pi-dynamic-workflows` supplies these with a separate registered `workflow` tool, a Node `vm` runner, extension hooks, and persistent run state; it may optionally load `builtin:codemode` *inside child sessions*, but that opt-in does not make codemode its workflow runner. [Pi codemode](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/codemode.md#scripts), [DW tool registration](https://github.com/QuintinShaw/pi-dynamic-workflows/blob/4df9c3d25b28eb0bc995ac2e265dafb3190a00ff/src/pi-extension.ts#L189-L190), [DW VM](https://github.com/QuintinShaw/pi-dynamic-workflows/blob/4df9c3d25b28eb0bc995ac2e265dafb3190a00ff/src/workflow.ts#L2189-L2204), [DW builtin opt-in](https://github.com/QuintinShaw/pi-dynamic-workflows/blob/4df9c3d25b28eb0bc995ac2e265dafb3190a00ff/README.md#model-tiers-and-run-controls).

**Limit of this research.** Documentation and targeted source inspection establish reference contracts, not a tested guarantee that Pi `codemode` can run asynchronous coding agents across turns, recover a stopped call, or expose the same UI. The new extension's Pi RPC/ACP integration and feasibility need their own investigation. The live Anthropic documentation may change; the pinned source versions above should remain the comparison baseline. [Pi codemode, execution/limits](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/codemode.md#scripts), [Anthropic docs](https://code.claude.com/docs/en/workflows).

**Proposals for later decisions, not findings:** Decide separately (1) whether saved scripts must be invocable as commands or only reusable through a codemode-facing interface, (2) whether resume must survive session/process exit or only pause within a live session, (3) whether explicit one-request opt-in and standing automatic mode should use the Claude `ultracode` wording or the Pi extension's `workflow`/`/ultracode` conventions, and (4) what controls, safety limits, and progress UI belong in the first release. These questions follow from the differences in the cited comparison, not from a claim that codemode already implements them.
